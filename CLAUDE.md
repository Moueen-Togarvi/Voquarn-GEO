# Voquarn GEO

A Generative Engine Optimization platform: measure how a brand appears in AI
answers and search, find competitor gaps with evidence, and produce reviewed
content against them.

Roadmap lives in `RankHunter_AI_Implementation_Plan.md` (strategy) and the
approved phased plan. Current state: **Phases 0, 1a, and 1b complete —
Phase 1c (project configuration v2) next.**

## Stack

Next.js 16 App Router · React 19 · TypeScript strict · Tailwind v4 (CSS-first,
no `tailwind.config`) · Prisma 7 → Neon Postgres via `@prisma/adapter-neon` ·
Zod 4 · Inngest 4 · Better Auth (organization plugin) · lucide-react ·
Vitest 4 · Playwright.

## Conventions

**Never edit `src/generated/prisma/`.** It is generated by `prisma generate`
(the `prisma-client` generator, not `prisma-client-js`) and gitignored.

**Data flow.** Server components import the service layer directly. Client
components `fetch()` the route handlers. There are no server actions — the
single planned exception is the Phase-1c onboarding wizard, which will use
React 19 `useActionState`.

**Route handlers** are a bare `try { … } catch (error) { return errorResponse(error) }`.
Throw `AppError(status, code, message, fieldErrors?)` from
`src/lib/api/errors.ts`; `errorResponse` also maps `SyntaxError` →
`INVALID_JSON`, `ZodError` → `VALIDATION_ERROR`, and Prisma `P2002` →
`DUPLICATE_BRAND`.

**Transport envelopes** (`ApiSuccess`, `ApiFailure`, `ApiAccepted`) live in
`src/lib/api/types.ts`. Domain modules own their own DTOs and must not
re-declare envelopes. DTOs serialize dates to ISO strings so they cross the
server/client boundary cleanly.

**Styling** is ~1300 lines of hand-written semantic CSS in
`src/app/globals.css` — `.button`, `.content-card`, `.page-container`,
`.form-alert`, `.metric-card`, and so on. Reuse those classes; do not introduce
Tailwind utility soup, shadcn, or cva. `cn()` in `src/lib/utils.ts` is a plain
join with no conflict resolution. Radix **primitives only** arrive in Phase 6.

**Accessibility is load-bearing** — e2e tests select by role and label. Keep
`role="alert"` on error text, `aria-live` on progress, `aria-invalid` on bad
inputs, and real `<label>` associations.

**Naming.** The database model is `Brand`; the UI and all user-facing strings
say "Project". This is deliberate — see `docs/adr/0004-brand-vs-project.md`.

**Auth is built but not enforced.** Better Auth (sessions, organizations,
roles, invitations) is fully wired, but `AUTH_ENABLED` defaults to `false` —
see `src/lib/auth/flag.ts`. While off, `requireWorkspaceContext()` falls back
to one shared default workspace and `proxy.ts` never redirects; sign-in,
sign-up, and the members UI stay in the codebase but are unreachable by
default. Flip `AUTH_ENABLED=true` once billing (Phase 8) is integrated —
there's no reason to make people create accounts before there's a plan to put
them on. Every new page/route should still call `requireWorkspaceContext()`
as normal; the flag is checked in exactly that one function plus `proxy.ts`,
nowhere else.

## Testing

Pure functions are extracted specifically so they can be tested without
network: `buildOpenAiRequest`, `buildDiscoveryMessages`,
`extractWebsiteSnapshot`, `selectRepresentativeWebsiteUrls`.
Follow that pattern — parsers, scorers, and extractors stay pure, and the I/O
shell around them stays thin.

Inject dependencies through constructor defaults (`new OpenAiProvider("test-key")`)
rather than mocking modules. Gate anything needing an external resource with
`describe.skipIf(...)`. Playwright never hits a live LLM: it sets
`E2E_DISCOVERY_FIXTURE=true`, which short-circuits to `fixtureProfile()`.

## Security invariants

- `assertPublicWebsiteUrl` has a three-state contract: `true` = verified
  public, `false` = DNS lookup failed (soft-fail, continue without a snapshot),
  **throws** `UnsafeWebsiteError` = definitively unsafe. Do not collapse it to a
  boolean.
- `readPublicWebsite` re-validates on every redirect hop. Keep it that way.
- `src/lib/discovery/website.ts` is server-only (`node:dns`, `node:net`). Only
  `src/lib/validation/brand.ts` helpers may be imported by client components.
- Secrets never travel through ordinary DTO paths.
